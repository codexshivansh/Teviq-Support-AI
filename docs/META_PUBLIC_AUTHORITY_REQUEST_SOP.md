# Public-authority data request SOP

**Owner:** Teviq Admin on duty  
**Effective:** 25 October 2026  
**Status:** Adopted for Teviq's handling of requests from public authorities

## Purpose and scope

Use this process whenever Teviq receives a formal request from a government or
public authority for a user's personal data, including Meta Platform Data. Do
not treat an informal message or an unverified sender as a valid request.

## Required steps

1. **Receive and preserve.** The Teviq Admin records the request date, authority,
   contact channel, stated legal basis, requested data, users/time period, and
   response deadline. Keep the request in an access-restricted company record;
   do not put request contents or user data in source control or general chat.
2. **Verify and review legality.** Before any disclosure, the Teviq Admin checks
   the sender's identity, the authority's jurisdiction, the legal instrument,
   the stated basis, and whether the request is valid and in scope. If any point
   is unclear, unusually broad, or would require disclosure, seek qualified
   legal advice or clarification before responding, while tracking the deadline.
3. **Minimize.** If the request is valid, identify only the data specifically
   required by it. Exclude unrelated users, messages, credentials, tokens, and
   other data outside its scope.
4. **Approve and disclose securely.** The Teviq Admin records the decision and
   its rationale, then provides only the approved minimum data through a
   verified secure channel. Do not disclose data on an informal request alone.
5. **Complete the record and notification check.** Record what data categories
   were disclosed, to whom, when, by whom, the legal basis/review rationale,
   and the transfer method. Notify affected users only when required or legally
   permitted; record if notification is prohibited or deferred by law.

## Meta App Review mapping

This process supports the following answers only while Teviq Admins follow it:

- Required review of the legality of requests.
- Data minimization: disclose only the minimum information required by a valid
  request.
- Documentation of requests and responses, including review rationale and
  actors involved.

This SOP does **not** claim that Teviq has a formal process or provision for
challenging unlawful requests. Do not select that Meta checkbox unless a
separate challenge process is adopted and followed. Do not submit the App
Review while any other required answer is incomplete.
